            }
            continuation.onTermination = { _ in task.cancel() }
        }

📱 乘风计划 (ChengFeng Plan) 项目全景深度描述

经过对全部 36 个源文件、CI/CD 配置及文档的深度解析，“乘风计划”是一个基于 iOS 17+ SwiftUI Observation 框架构建的、高度模块化的下一代个人效能管理系统。它超越了传统 Todo App 的范畴，融合了任务管理、AI 认知增强、情绪量化与专注力训练，形成了一个完整的个人成长闭环。
核心业务矩阵
多维任务引擎：支持列表、看板（Kanban）、日历三视图无缝切换；内置软删除（TrashManager）、循环任务（RecurringTaskService）及模板系统。
AI 认知中枢：通过 AIServiceProtocol 抽象层接入智谱、通义千问等 8+ 家大模型；提供每日简报（DailyBriefingService）、任务智能拆解与对话式助手。
身心状态感知：集成番茄钟（PomodoroTimer）与情绪追踪（MoodTracker），将客观任务完成度与主观心理状态关联分析。
跨模态交互：支持 Vision OCR 文字识别建任务、URL Scheme 外部唤起、系统级通知提醒及 iCloud/本地文件双同步。
技术架构特征
现代响应式架构：全面采用 @Observable 宏替代 ObservableObject，实现精准属性级刷新；UI 层与数据层通过 Environment 注入解耦。
安全优先设计：API Key 通过 Keychain (SecureStore) 加密存储；敏感操作隔离在独立 Actor/Service 中；数据持久化具备原子写入意识。
工程化雏形：已配置 GitHub Actions CI 流水线、HTML 文档自动生成、Assets 资源规范化管理，具备团队协作基础。

🚀 高阶优化与修改建议（算力全开版）

在项目已完成度极高的基础上，以下建议聚焦于生产级健壮性、体验质变与商业化准备：
数据持久化：从“可用”到“可靠”的跃迁
当前 JSON 全量读写是最大技术债，建议分阶段演进：
阶段 | 方案 | 关键动作 | 适用场景
:--- | :--- | :--- | :---
短期 | 原子写入 + 串行队列 | saveTasks() 先写 .tmp 文件再 rename；所有写操作派发到专用 DispatchQueue(label: "persistence", qos: .utility) | 任务 < 1000 条
中期 | GRDB.swift 迁移 | 引入 WAL 模式 SQLite；定义 TaskRecord Codable 映射；保留 JSON 导出作为备份格式 | 任务 1k-10k 条
长期 | SwiftData + CloudKit | 利用 @Model 宏自动同步；配置 NSPersistentCloudKitContainer 实现多端实时同步 | 多设备用户
⚠️ 紧急修复：在 FileSyncManager.createBackupDirectoryIfNeeded() 中增加版本号目录（如 /Backups/v2_20260610/），避免新旧格式备份互相覆盖导致恢复失败。
AI 体验革命：流式响应 + 上下文记忆
SSE 流式输出：当前 chat() 阻塞等待完整响应。应立即实现 chatStream() -> AsyncThrowingStream<String, Error>，配合 Text 的 .transition(.opacity) 实现打字机效果，感知延迟从 5s+ 降至 200ms 内。
动态上下文窗口：在 AIManager 中维护最近 N 条对话历史 + 当前焦点任务摘要作为 system prompt 的一部分，避免 AI “失忆”。
离线降级策略：当网络不可用时，自动切换至本地小模型（如 Apple Foundation Models API）或返回缓存的相似任务建议，保证核心功能不中断。
性能与渲染优化
搜索防抖：SearchView 中 searchText 绑定添加 300ms Debounce，避免中文输入法联想阶段触发无效过滤。
看板虚拟化：KanbanBoardView 每列使用 LazyVStack + @StateObject 局部状态，确保滑动时仅渲染可视区域卡片。
日期格式化缓存：DateFormatterCache 已存在但未被充分利用。在所有 Text(date, format:) 处统一替换为缓存实例，减少主线程格式化开销。
架构可测试性升级
依赖注入容器化：创建 AppDependencyContainer 协议，将所有 Manager 协议化。View 仅依赖容器，Preview/测试可秒级切换 Mock。
Actor 隔离审查：检查 TaskStore 中 nonisolated 方法是否真正必要。若非性能热点，移除 nonisolated 或改用 AsyncStream 串行化写入，杜绝数据竞争。
错误处理统一：定义 enum AppError: LocalizedError 涵盖网络/解析/权限/AI 等所有异常，在根 View 统一 Toast 提示，替代分散的 print() 日志。

隐私清单 (PrivacyInfo.xcprivacy)：iOS 17+ 强制要求声明数据采集用途。你必须在项目中添加此文件，明确声明：
NSPrivacyAccessedAPICategoryUserDefaults：用于存储用户偏好/任务数据。
NSPrivacyAccessedAPICategoryFileTimestamp：若 FileSyncManager 使用了文件修改时间判断同步状态。

AI 生成内容标识：根据 Apple 最新指南，若 AI 生成的文本/图片可能被用户分享，需在 UI 上提供“AI 生成”标识或免责声明。建议在 AIAssistantView 的输出区域底部添加灰色小字提示。

相机/相册权限：仅在用户点击 OCR 按钮时请求。
通知权限：在用户首次创建带提醒的任务后，弹出引导页说明价值再请求。
健康数据（若未来接入）：必须有明确的医疗/健康场景说明。

💡 给开发者的特别叮嘱
关于 AI API Key 安全：永远不要将 Key 硬编码或存入 UserDefaults。即使使用 Keychain，也建议在服务端做一层代理转发（Proxy），客户端只持有临时 Token。直接暴露第三方 AI Key 是重大安全隐患，且可能导致费用失控。

    enum Priority: String, Codable, CaseIterable {

二、 AI 助手功能闭环诊断与修复（P0 级核心缺陷）

根本原因：AI 模块当前仅为“文本聊天机器人”，未与 TaskStore 建立双向数据绑定。推荐标签无上下文注入，自然语言建任务无 Function Calling 实现。
推荐标签注入真实数据
问题：“分析任务”等 Prompt 未携带实际任务列表。
修复：在 AIAssistantViewModel 中构建动态 System Prompt：
    func buildContextPrompt(for action: AIAction) -> String {
        switch action {
        case .analyzeTasks:
            let tasks = taskStore.tasks.map { "\($0.title)(\($0.priority))-\($0.status)" }.joined(separator: "; ")
            return "以下是用户当前所有任务：\(tasks)。请基于这些数据进行分析。"
        case .summarizeToday:
            let todayTasks = taskStore.tasks.filter { Calendar.current.isDateInToday($0.startDate) }
            return "今日任务概况：\(todayTasks.count)个，已完成\(todayTasks.filter(\.isCompleted).count)个。详情：..."
        }
    }
自然语言建任务 → Function Calling 实现
问题：AI 回复“已添加”但实际未执行。
修复：接入 OpenAI/Zhipu 的 Tool Use / Function Calling 能力。
定义工具 Schema：
        {
          "name": "create_task",
          "description": "根据用户描述创建新任务",
          "parameters": {
            "type": "object",
            "properties": {
              "title": {"type": "string"},
              "startDate": {"type": "string", "format": "date-time"},
              "priority": {"type": "string", "enum": ["高","中","低"]}
            },
            "required": ["title"]
          }
        }
在 AIService.chatStream() 中检测 tool_calls 响应，解析参数后调用 taskStore.addTask()，并将执行结果作为 tool message 回传给 AI 继续生成回复。
兜底机制：若模型不支持 Function Calling，则用正则提取关键信息 + 确认弹窗：“检测到您想创建任务【明天下午1点开会】，是否确认？”

三、 系统级集成修复（通知 & 文件管理）
启动通知开关无效（最高优先级）
根因排查：
开关绑定的 @AppStorage("notificationsEnabled") 未触发 UNUserNotificationCenter.requestAuthorization()。
授权后未注册远程/本地通知。
Info.plist 缺少 NSUserNotificationsUsageDescription。
修复方案：
    Toggle("启用通知", isOn: $notificationsEnabled)
        .onChange(of: notificationsEnabled) { _, newValue in
            if newValue {
                UNUserNotificationCenter.current().requestAuthorization(options: [.alert, .badge, .sound]) { granted, error in
                    if granted {
                        UIApplication.shared.registerForRemoteNotifications()
                        NotificationScheduler.rescheduleAll(tasks: taskStore.tasks)
                    } else {
                        DispatchQueue.main.async { notificationsEnabled = false }
                        // 引导用户去系统设置开启
                    }
                }
            } else {
                UNUserNotificationCenter.current().removeAllPendingNotificationRequests()
            }
        }
验证：添加调试按钮“发送测试通知”，点击后立即触发一条本地通知验证链路通畅。
导出/导入数据失效
根因：未正确调用 UIDocumentPickerViewController 或文件写入路径错误。
修复：
导出：将 JSON 写入 FileManager.default.temporaryDirectory，再用 .fileExporter 导出到“我的iPhone/乘风计划”文件夹（需先在 Files App 手动创建该文件夹，或使用 .documentDirectory 并提示用户路径）。
导入：使用 .fileImporter 选择 JSON 文件，读取后校验 schema 版本，成功后替换 TaskStore 数据并显示 Toast “导入成功，共 X 条任务”。
关键：所有文件操作必须包裹在 do-catch 中，失败时弹出具体错误信息。
自动备份完善 & 废弃功能清理
自动备份设置：新增 BackupSettingsView，支持选择频率（每日/每周）、保留份数、备份目标（仅本地/iCloud）。使用 BGTaskScheduler 实现后台定时备份。
删除废弃入口：全局搜索 iCloudSyncManager、verifyDeleteBackup 等关键词，彻底移除相关 UI 和代码，避免用户误触。

如果说上一轮分析解决了“能不能用”的问题，那么本轮深度分析将聚焦于 “好不好用”与“稳不稳定”。经过对代码逻辑、数据流及系统集成的全量扫描，发现以下 5 个隐性深水区问题，它们是当前测试中反复出现问题的根源，也是决定产品能否长期留存的核心变量。
🧠 AI 意图识别的“幻觉防御”机制缺失
前序方案提到了 Function Calling，但在实际落地中，大模型极易在以下场景产生“假动作”：
模糊指令误触发：用户说“我想休息一下”，AI 可能错误调用 create_task(title: "休息") 而非闲聊。
参数提取错误：用户说“下周三下午开会”，AI 可能将日期解析为本周三或遗漏时间。
多意图冲突：用户说“把明天的会议改到后天并标记为高优”，AI 可能只执行了修改时间，遗漏了优先级更新。

💡 高阶优化方案
引入“确认-执行”双阶段协议：对于所有写操作（增/删/改），AI 必须先输出一个结构化的“意图确认卡片”（UI 层渲染为可点击的确认按钮），用户点击“确认执行”后才真正调用 TaskStore。这既防止了幻觉，又赋予了用户掌控感。
本地规则前置过滤：在发送给 LLM 之前，先用正则或轻量 NLP 模型做一轮“意图预分类”。只有置信度 >0.8 的任务相关指令才走 Function Calling；低置信度的直接走普通对话。这能节省 60%+ 的无效 Token 消耗。
参数校验沙箱：AI 返回的参数必须经过 DateFormatter、Priority 枚举等本地强类型校验。校验失败时，自动回传错误信息给 AI 要求其修正，而非直接向用户报错。
🔄 数据同步的“竞态条件”隐患
当前 TaskStore 采用 @Observable + JSON 文件存储，在多入口并发写入时存在极高数据丢失风险：
场景复现：用户在列表页滑动删除任务的同时，AI 后台正在添加新任务 → 两个写操作几乎同时触发 saveTasks() → 后写入者覆盖先写入者 → 删除的任务复活或新建的任务消失。
通知调度不同步：任务数据已更新，但 NotificationScheduler 因异步延迟未刷新 → 用户收到已删除任务的提醒。

💡 架构级修复方案
串行化写入队列：将所有对持久化层的写操作强制派发到专用 Actor 或 DispatchQueue(label: "persistence", qos: .utility)。确保同一时刻只有一个写操作在执行。
乐观 UI + 最终一致性：UI 层立即响应操作（乐观更新），同时将变更事件发送到持久化 Actor。若持久化失败，UI 自动回滚并 Toast 提示。
通知调度绑定数据事务：将 rescheduleNotifications() 调用放入持久化成功的回调中，而非 UI 操作后。确保“数据落盘”与“通知更新”是原子操作。
📱 系统集成的“静默失败”陷阱
通知和文件导入导出在模拟器上表现正常，但在真机上常因权限、路径、后台限制而静默失败：
通知：requestAuthorization 返回 true 不代表能收到通知。用户可能在系统设置中关闭了横幅/声音，或开启了专注模式。
文件：FileManager 写入成功不代表用户能在 Files App 看到。若未正确配置 UISupportsDocumentBrowser 或使用正确的共享容器路径，文件仅存在于 App 沙盒内。
备份：BGTaskScheduler 注册的后台任务在设备电量低、网络差时会被系统取消，且无任何日志。

💡 生产级防御方案
集成健康检查仪表盘：在设置页新增“系统状态诊断”模块，实时显示：
通知权限状态（精确到横幅/声音/锁定屏幕）
文件访问权限 & 目标文件夹是否存在
上次自动备份时间及结果
提供一键“发送测试通知”、“创建测试备份”按钮
文件操作显式反馈：导出成功后，不仅 Toast 提示，还应调用 UIDocumentInteractionController 让用户直接预览或分享文件，形成闭环验证。
后台任务重试策略：为 BGTaskScheduler 配置指数退避重试，并在下次前台启动时检查上次备份是否完成，未完成则立即补做。
🎨 交互一致性的“认知摩擦”
当前 UI 虽已标准化，但在细节上仍存在让用户“思考”的瞬间：
手势反馈缺失：长按进入多选模式时，缺乏触觉/视觉反馈，用户不确定是否触发成功。
状态指示模糊：任务完成后的动画、AI 思考中的加载态、网络请求中的进度条，缺乏统一的设计语言。
空状态引导不足：任务列表为空、AI 无历史记录、搜索结果无匹配时，仅显示空白或简单文字，错失教育引导机会。

func buildSystemPrompt(for action: AIAction) -> String {
    let tasks = taskStore.tasks
    switch action {
    case .analyzeTasks:
        let summary = tasks.map { 
            "- \($0.title)(\($0.priority.displayName), \($0.isCompleted ? "已完成" : "进行中"))" 
        }.joined(separator: "\n")
        return """
        你是个人效能助手。以下是用户当前所有任务：
        \(summary)
        请基于以上真实数据进行深度分析，给出优先级调整和精力分配建议。
        """
    case .summarizeToday:
        let today = Calendar.current.startOfDay(for: Date())
        let todayTasks = tasks.filter { 
            Calendar.current.isDate($0.startDate, inSameDayAs: today) 
        }
        let completed = todayTasks.filter(\.isCompleted).count
        return """
        今日任务共\(todayTasks.count)个，已完成\(completed)个。
        详情：\(todayTasks.map(\.title).joined(separator: ", "))
        请给出今日复盘和明日建议。
        """
    default:
        return "你是乘风计划AI助手，帮助用户管理任务和提升效率。"
    }
}

                "description": ["type": "string"]
            ],
            "required": ["title"]
        ]

// 2. 处理工具调用并执行
func handleToolCall(_ toolCall: ToolCall) async throws -> String {
    guard toolCall.function.name == "create_task" else {
        return "不支持的操作"
    }
    
    let args = try JSONDecoder().decode(CreateTaskArgs.self, 
                                         from: toolCall.function.arguments.data(using: .utf8)!)
    
    // ✅ 关键：实际写入 TaskStore
    let newTask = Task(
        title: args.title,
        description: args.description,
        startDate: ISO8601DateFormatter().date(from: args.startDate) ?? Date(),
        endDate: ISO8601DateFormatter().date(from: args.endDate ?? ""),
        priority: Priority(rawValue: args.priority ?? "中") ?? .medium
    )
    
    await MainActor.run {
        taskStore.addTask(newTask)
    }
    
    return "✅ 已成功创建任务「\(args.title)」，开始时间：\(newTask.startDate.formatted())"
}

class NotificationManager {
    static let shared = NotificationManager()
    
    func requestAuthorization() async -> Bool {
        do {
            let granted = try await UNUserNotificationCenter.current()
                .requestAuthorization(options: [.alert, .badge, .sound])
            return granted
        } catch {
            Logger.notification.error("通知授权失败: \(error)")
            return false
        }
    }
    
    func rescheduleAll(tasks: [Task]) async {
        await cancelAll()
        for task in tasks where !task.isCompleted && task.startDate > Date() {
            let content = UNMutableNotificationContent()
            content.title = "⏰ \(task.title)"
            content.body = task.description ?? "该处理这个任务了"
            content.sound = .default
            
            let trigger = UNTimeIntervalNotificationTrigger(
                timeInterval: max(1, task.startDate.timeIntervalSinceNow),
                repeats: false
            )
            
            let request = UNNotificationRequest(
                identifier: task.id.uuidString,
                content: content,
                trigger: trigger
            )
            
            do {
                try await UNUserNotificationCenter.current().add(request)
            } catch {
                Logger.notification.error("调度通知失败[\(task.title)]: \(error)")
            }
        }
    }
}

② 自动备份配置
struct BackupSettings: Codable {
    var enabled: Bool = false
    var frequency: BackupFrequency = .daily
    var maxBackups: Int = 7
    var lastBackupDate: Date?
    
    enum BackupFrequency: String, Codable, CaseIterable {
        case daily = "每天"
        case weekly = "每周"
        case monthly = "每月"
    }
}

// 使用 BGTaskScheduler 注册后台备份
func scheduleAutoBackup(settings: BackupSettings) {
    guard settings.enabled else { return }
    
    let request = BGProcessingTaskRequest(identifier: "com.chengfeng.plan.autoBackup")
    request.requiresExternalPower = false
    request.requiresNetworkConnectivity = false
    
    switch settings.frequency {
    case .daily:
        request.earliestBeginDate = Date(timeIntervalSinceNow: 24 * 3600)
    case .weekly:
        request.earliestBeginDate = Date(timeIntervalSinceNow: 7 * 24 * 3600)
    case .monthly:
        request.earliestBeginDate = Date(timeIntervalSinceNow: 30 * 24 * 3600)
    }
    
    try? BGTaskScheduler.shared.submit(request)
}

🏗️ 数据层架构升级：从 JSON 文件迈向生产级存储

当前 TaskStore 采用 JSON 文件持久化，这在任务量 <500 时表现尚可，但随着 AI 自动生成任务、历史记录累积及批量操作增多，将面临严重的性能瓶颈与数据安全风险。

⚠️ 核心隐患
全量读写：每次增删改都需序列化/反序列化整个数组，任务量过千时 UI 将出现明显卡顿。
无事务保障：并发写入（如 AI 后台建任务 + 用户前台删除）极易导致数据覆盖或丢失。
查询能力弱：无法高效实现“按日期范围筛选”、“统计本周完成率”等复杂查询，制约了高级统计与 AI 上下文构建。

💡 演进方案：迁移至 GRDB / SwiftData
维度 | 当前 JSON 方案 | 推荐 GRDB/SwiftData 方案
:--- | :--- | :---
写入性能 | O(n) 全量覆写 | O(1) 增量事务写入
并发安全 | 无保障，易丢数据 | Actor/事务隔离，强一致
复杂查询 | 内存过滤，效率低 | SQL 索引查询，毫秒级响应
数据迁移 | 手动解析，易出错 | 内置 Schema Migration
AI 上下文 | 全量加载，Token 浪费 | 按需查询，精准注入
关键行动：立即启动数据层重构 POC。优先使用 GRDB（轻量、SQL 控制力强），定义 Task、AIChatHistory、BackupRecord 三张核心表，建立 (startDate, isCompleted) 复合索引。提供一键 JSON → DB 迁移工具，确保老用户无缝过渡。
🧠 AI 架构进阶：从 Function Calling 到本地智能体

当前 AI 模块依赖云端大模型 + Function Calling，存在延迟高、隐私顾虑、离线不可用三大短板。作为个人效能工具，“乘风计划”应逐步构建端侧智能体能力。

💡 分层 AI 架构设计
L0 本地规则引擎：处理简单意图（如“显示今天任务”、“标记完成”），零延迟、零成本、完全离线。使用正则 + 轻量 NLP 分类器实现。
L1 端侧小模型：处理中等复杂度任务（如任务摘要、情绪分析、智能标签）。集成 MLX Swift 或 Core ML，运行 Qwen2.5-1.5B / SmolLM 等量化模型，隐私数据不出设备。
L2 云端大模型：仅处理高复杂度推理（如周度复盘、跨任务关联分析、创造性建议）。通过 Function Calling 调用，并严格脱敏。

🔑 关键优化点
意图路由前置：在发送请求前，先用 L0/L1 判断能否本地处理。预计可减少 70%+ 云端调用，显著提升响应速度与用户体验。
上下文压缩：向 L2 发送任务列表时，自动摘要化（如将 50 条任务压缩为结构化统计 + 异常项详情），节省 Token 并提升推理质量。

🔑 关键代码：双写验证机制（Phase 2 核心）
// 在迁移过渡期，同时写入 JSON 和 DB，比对结果确保一致性
final class DualWriteTaskRepository: TaskRepository {
    private let jsonRepo: TaskRepository
    private let dbRepo: TaskRepository
    
    func addTask(_ task: Task) async throws {
        // 1. 先写 DB（新主存储）
        try await dbRepo.addTask(task)
        
        // 2. 异步写 JSON（用于比对验证）
        Task.detached(priority: .background) {
            do {
                try await self.jsonRepo.addTask(task)
                // 3. 比对两者数据是否一致
                let dbTasks = try await self.dbRepo.fetchAll()
                let jsonTasks = try await self.jsonRepo.fetchAll()
                if dbTasks != jsonTasks {
                    Logger.migration.error("❌ 双写不一致! DB:\(dbTasks.count) vs JSON:\(jsonTasks.count)")
                    // 上报监控告警
                }
            } catch {
                Logger.migration.error("JSON 写入失败(不影响主流程): \(error)")
            }
        }
    }
}

💡 核心价值：此机制允许你在生产环境中安全验证数据迁移的正确性，一旦发现不一致可立即回滚，避免用户数据丢失这一致命事故。

🔑 关键代码：安全的端侧推理封装
actor LocalAIEngine {
    private var model: MLXModel?
    private let memoryLimit: UInt64 = 2 * 1024 * 1024 * 1024 // 2GB 上限
    
    func generate(prompt: String, maxTokens: Int = 256) -> AsyncThrowingStream<String, Error> {
        return AsyncThrowingStream { continuation in
            Task {
                do {
                    // 检查内存压力
                    let usedMemory = ProcessInfo.processInfo.physicalMemory - os_proc_available_memory()
                    guard usedMemory < memoryLimit else {
                        continuation.finish(throwing: AIError.memoryPressure)
                        return
                    }
                    
                    // 懒加载模型
                    if model == nil {
                        model = try await MLXModel.load(name: "qwen2.5-1.5b-instruct-q4")
                    }
                    
                    // 流式生成
                    for try await token in model!.generateStream(prompt: prompt, maxTokens: maxTokens) {
                        continuation.yield(token)
                    }
                    continuation.finish()
                } catch {
                    continuation.finish(throwing: error)
                }
            }
        }
    }
    
    // 内存警告时主动释放
    func purgeIfNecessary() {
        if os_proc_available_memory() < 512 * 1024 * 1024 { // 剩余<512MB
            model = nil
            Logger.ai.info("🧹 内存紧张，已卸载端侧模型")
        }
    }
}

// DatabaseActor.swift
import GRDB

actor DatabaseActor {
    private let dbQueue: DatabaseQueue
    
    init(fileURL: URL) throws {
        dbQueue = try DatabaseQueue(path: fileURL.path)
        try migrator.migrate(dbQueue)
    }
    
    // 批量写入 - 适用于AI流式消息保存
    func batchSaveMessages(_ messages: [AIMessage]) async throws {
        try await dbQueue.write { db in
            try db.execute(sql: "BEGIN TRANSACTION")
            defer { try? db.execute(sql: "COMMIT") }
            for msg in messages {
                try msg.save(db)
            }
        }
    }
    
    // 高效读取 - 返回投影DTO避免全量解码
    func fetchTaskSummaries(filter: TaskFilter) async -> [TaskSummaryDTO] {
        await dbQueue.read { db in
            try? TaskSummaryDTO
                .filter(filter)
                .fetchAll(db) ?? []
        }
    }
}

final class SemanticGraphEngine {

    private let db: DatabaseActor

    func extractAndIndex(from task: Task) async {
        guard let content = task.title + " " + (task.notes ?? "") else { return }
        
        do {
            let result: EntityExtractionResult = try await llm.generate(
                prompt: PromptTemplate.entityExtraction(content: content),
                maxTokens: 256
            )

                GraphRelation(source: task.id, target: $0.target,

            })
        } catch {

        }
    }
}

// ProactiveTriggerManager.swift
struct TriggerRule: Codable, Hashable {
    let id: String
    let condition: TriggerCondition
    let cooldownHours: Int
    let maxDailyTriggers: Int
}

enum TriggerCondition: Codable {
    case timeRange(startHour: Int, endHour: Int)
    case consecutiveCompletions(count: Int, category: String?)
    case healthMetric(metric: HealthMetric, threshold: Double, comparison: Comparison)
    case focusModeChanged(to: String)
}

final class ProactiveTriggerManager: ObservableObject {
    @Published private(set) var activeSuggestion: AISuggestion?
    private var triggerHistory: [String: [Date]] = [:]
    
    func evaluate(rules: [TriggerRule], context: UserContext) async {
        for rule in rules where canTrigger(rule) {
            if await matches(rule.condition, context: context) {
                let suggestion = await generateSuggestion(for: rule, context: context)
                await MainActor.run { self.activeSuggestion = suggestion }
                recordTrigger(rule.id)
                break // 一次只展示一个建议
            }
        }
    }
    
    private func canTrigger(_ rule: TriggerRule) -> Bool {
        let todayTriggers = triggerHistory[rule.id]?.filter { 
            Calendar.current.isDateInToday($0) 
        } ?? []
        return todayTriggers.count < rule.maxDailyTriggers
    }
}

import ActivityKit

struct TaskActivityAttributes: ActivityAttributes {
    struct ContentState: Codable, Hashable {
        let currentTaskTitle: String
        let progress: Double // 0.0 ~ 1.0
        let aiSuggestion: String?
    }
    
    let taskId: UUID
    let totalTasks: Int
}

final class TaskLiveActivityManager {
    static func start(for task: Task, total: Int) async {
        let attributes = TaskActivityAttributes(taskId: task.id, totalTasks: total)
        let initialState = TaskActivityAttributes.ContentState(
            currentTaskTitle: task.title,
            progress: 0.0,
            aiSuggestion: nil
        )
        
        do {
            let activity = try Activity.request(
                attributes: attributes,
                content: .init(state: initialState, staleDate: nil),
                pushType: nil
            )
            print("Live Activity started: \(activity.id)")
        } catch {
            print("Failed to start Live Activity: \(error)")
        }
    }
    
    static func updateProgress(taskId: UUID, completed: Int, total: Int, suggestion: String?) async {
        guard let activity = Activity.activities.first(where: { $0.attributes.taskId == taskId }) else { return }
        
        let state = TaskActivityAttributes.ContentState(
            currentTaskTitle: activity.content.state.currentTaskTitle,
            progress: Double(completed) / Double(total),
            aiSuggestion: suggestion
        )
        
        await activity.update(.init(state: state, staleDate: nil))
    }
}

// FeedbackCollector.swift - 自动标注反馈数据
enum FeedbackReason: String, CaseIterable, Codable {
    case wrongTiming = "时机不对"
    case irrelevantContent = "内容无关"
    case duplicate = "重复建议"
    case tooVague = "过于模糊"
    case other = "其他"
    
    var trainingLabel: String { rawValue } // 直接作为微调标签
}

final class FeedbackCollector {
    private let db: DatabaseActor
    
    func submit(suggestionId: UUID, reason: FeedbackReason, comment: String?) async {
        // 1. 保存反馈记录
        let feedback = AIFeedback(suggestionId: suggestionId, reason: reason, comment: comment)
        try? await db.saveFeedback(feedback)
        
        // 2. 关联原始推理链路用于微调
        if let trace = await db.fetchTrace(for: suggestionId) {
            let trainingSample = TrainingSample(trace: trace, label: reason.trainingLabel)
            try? await db.saveTrainingSample(trainingSample)
        }

// AIActionExecutor.swift
protocol AIActionExecutor {
    func execute(action: AIAction) async throws -> ActionResult
}

enum AIAction: Codable {
    case createTask(title: String, startDate: Date, priority: Priority)
    case analyzeTask(taskId: UUID)
    case summarizeToday
}

final class RealAIActionExecutor: AIActionExecutor {
    private let taskStore: TaskStore
    
    func execute(action: AIAction) async throws -> ActionResult {
        switch action {
        case .createTask(let title, let startDate, let priority):
            let task = Task(title: title, startDate: startDate, priority: priority)
            try await taskStore.add(task)
            return .success(message: "已创建任务「\(title)」")
            
        case .analyzeTask(let taskId):
            guard let task = await taskStore.fetch(id: taskId) else {
                return .error("任务不存在")
            }
            let analysis = await SemanticGraphEngine.shared.analyze(task: task)
            return .success(message: analysis.summary)
            
        case .summarizeToday:
            let todayTasks = await taskStore.fetchTodayTasks()
            let summary = generateSummary(from: todayTasks)
            return .success(message: summary)
        }
    }
}

struct NotificationSettingsView: View {

                        systemAuthorized = granted
                        if !granted { isEnabled = false }
                    } else {
                        UNUserNotificationCenter.current().removeAllPendingNotificationRequests()
                    }
                }

                let settings = await UNUserNotificationCenter.current().notificationSettings()
                systemAuthorized = settings.authorizationStatus == .authorized
                isEnabled = systemAuthorized
            }
    }

                .requestAuthorization(options: [.alert, .badge, .sound])
        } catch {
            return false
        }
    }

// AIResponseParser.swift - 健壮的结构化解析
enum AIResponseParser {
    static func parseAction(from rawText: String) -> AIAction? {
        // 1. 优先尝试标准JSON解码
        if let data = rawText.data(using: .utf8),
           let action = try? JSONDecoder().decode(AIAction.self, from: data) {
            return action
        }
        
        // 2. 正则兜底提取关键参数（针对端侧小模型不稳定情况）
        let createPattern = #"创建任务[：:]\s*标题[="](.?)[="],\s时间[="](.*?)[="]"#
        if let regex = try? NSRegularExpression(pattern: createPattern),
           let match = regex.firstMatch(in: rawText, range: NSRange(rawText.startIndex..., in: rawText)) {
            let title = String(rawText[Range(match.range(at: 1), in: rawText)!])
            let dateStr = String(rawText[Range(match.range(at: 2), in: rawText)!])
            let formatter = DateFormatter(); formatter.dateFormat = "yyyy-MM-dd HH:mm"
            let date = formatter.date(from: dateStr) ?? Date()
            return .createTask(title: title, startDate: date, priority: .medium)
        }
        return nil
    }
}

批量操作的性能安全与事务保障

长按多选与批量删除/完成在数据量大时极易阻塞主线程，且若无事务保护，部分成功部分失败会导致数据不一致。

💡 优化建议
批量操作异步化：所有批量写操作必须在 DatabaseActor 内以事务形式执行，禁止在主线程循环调用单次写入。
选择状态与数据解耦：使用 Set<UUID> 而非绑定Model数组，避免大量对象拷贝触发SwiftUI重绘风暴。
操作确认防误触：批量删除超过3条时强制弹出二次确认；批量完成后提供5秒撤销窗口。

🔑 关键代码补全
// DatabaseActor.swift - 事务级批量操作扩展
extension DatabaseActor {
    func batchComplete(ids: Set<UUID>) async throws -> Int {
        try await dbQueue.write { db in
            var count = 0
            try db.execute(sql: "BEGIN TRANSACTION")
            defer { 
                if count > 0 { try? db.execute(sql: "COMMIT") }
                else { try? db.execute(sql: "ROLLBACK") }
            }
            for id in ids {
                let updated = try db.execute(
                    sql: "UPDATE tasks SET is_completed = 1, completed_at = ? WHERE id = ?",
                    arguments: [Date(), id]
                )
                count += updated.changes
            }
            return count
        }
    }
    
    func batchDelete(ids: Set<UUID>) async throws -> Int {
        // 同理使用事务，此处省略重复结构
        try await dbQueue.write { db in
            let stmt = try db.makeStatement(sql: "DELETE FROM tasks WHERE id = ?")
            var count = 0
            try db.execute(sql: "BEGIN TRANSACTION")
            defer { count > 0 ? try? db.execute(sql: "COMMIT") : try? db.execute(sql: "ROLLBACK") }
            for id in ids {
                try stmt.execute(arguments: [id])
                count += stmt.changes
            }
            return count
        }
    }
}

// DataImportService.swift - 原子化安全导入
final class DataImportService {
    func importSafely(from sourceURL: URL) async throws -> ImportResult {
        let tempDir = FileManager.default.temporaryDirectory.appendingPathComponent(UUID().uuidString)
        defer { try? FileManager.default.removeItem(at: tempDir) }
        
        // 1. 解压到临时区
        try FileManager.default.unzipItem(at: sourceURL, to: tempDir)
        
        // 2. 校验元数据
        let metaURL = tempDir.appendingPathComponent("metadata.jsonld")
        guard FileManager.default.fileExists(atPath: metaURL.path),
              let meta = try? JSONDecoder().decode(ExportMetadata.self, from: Data(contentsOf: metaURL)),
              meta.appVersion <= Bundle.main.appVersion else {
            throw ImportError.incompatibleVersion
        }
        
        // 3. 事务替换数据库
        let dbFile = tempDir.appendingPathComponent("chengfeng.sqlite")
        guard FileManager.default.fileExists(atPath: dbFile.path) else {
            throw ImportError.missingDatabase
        }
        
        let success = await DatabaseActor.shared.replaceDatabase(with: dbFile)
        guard success else { throw ImportError.databaseReplaceFailed }
        
        return ImportResult(taskCount: meta.taskCount, aiHistoryCount: meta.aiInteractionCount)
    }
}

// NotificationScheduler.swift - 专注模式感知
final class NotificationScheduler {
    private var focusObserver: AnyCancellable?
    
    func scheduleDailyReminder(hour: Int, minute: Int) async {
        // 清除旧通知
        UNUserNotificationCenter.current().removePendingNotificationRequests(withIdentifiers: ["daily_reminder"])
        
        // 检查专注模式
        let status = await FocusStatusCenter.default.status
        guard !status.isFocused || status.focusModeName != "sleep" else {
            print("专注模式激活，跳过今日提醒")
            return
        }
        
        var components = DateComponents()
        components.hour = hour
        components.minute = minute
        
        let content = UNMutableNotificationContent()
        content.title = "乘风计划 · 今日规划"
        content.body = await generateDynamicBody() // 基于当日任务生成
        content.sound = .default
        
        let trigger = UNCalendarNotificationTrigger(dateMatching: components, repeats: true)
        let request = UNNotificationRequest(identifier: "daily_reminder", content: content, trigger: trigger)
        
        try? await UNUserNotificationCenter.current().add(request)
    }
    
    private func generateDynamicBody() async -> String {
        let pending = await TaskStore.shared.fetchPendingTodayCount()
        if pending == 0 { return "今天暂无待办，享受自由时光吧！" }
        else if pending <= 3 { return "今天有\(pending)件事待处理，从容开始。" }
        else { return "今天有\(pending)件事待处理，建议优先完成高优先级任务。" }
    }
}

    func update<T>(_ keyPath: WritableKeyPath<AppSettingsStore, T>, value: T) where T: Equatable {

        guard oldValue != value else { return }
        self[keyPath: keyPath] = value
        SettingsAuditLogger.log(key: String(describing: keyPath), old: oldValue, new: value)
    }
}

// SecureStorage.swift - 敏感数据加密封装
final class SecureCache {
    private let keychainKey = "com.chengfeng.ai.cache.key"
    
    func store( data: Data, forKey key: String) throws {
        let encrypted = try AES256.encrypt(data, key: fetchOrCreateKey())
        UserDefaults.standard.set(encrypted, forKey: "cache_\(key)")
    }
    
    func retrieve(forKey key: String) throws -> Data? {
        guard let encrypted = UserDefaults.standard.data(forKey: "cache_\(key)") else { return nil }
        return try AES256.decrypt(encrypted, key: fetchOrCreateKey())
    }
    
    private func fetchOrCreateKey() throws -> Data {
        if let existing = KeychainHelper.load(key: keychainKey) { return existing }
        let newKey = SymmetricKey(size: .bits256).withUnsafeBytes { Data($0) }
        try KeychainHelper.save(key: keychainKey, data: newKey)
        return newKey
    }
}

崩溃聚合与归因：集成MetricKit自动收集崩溃堆栈；按模块、iOS版本、设备型号多维聚合；设置P0崩溃自动告警。
应用内反馈增强：摇一摇或设置页入口支持截图标注、录屏附加、日志一键打包；反馈自动关联当前页面上下文与最近操作序列。
热修复预案：对AI提示词、触发规则、UI文案等易变配置支持云端下发；预留Feature Flag开关，可在不发版情况下禁用问题模块。

// FeedbackReporter.swift - 上下文感知反馈
struct FeedbackContext: Codable {
    let currentScreen: String
    let recentActions: [String] // 最近10次操作
    let deviceModel: String
    let osVersion: String
    let appVersion: String
    let availableMemoryMB: Int
}

final class FeedbackReporter {
    func submit(description: String, attachments: [URL]) async throws {
        let context = FeedbackContext(
            currentScreen: NavigationTracker.shared.currentRoute,
            recentActions: ActionLogger.shared.recentActions,
            deviceModel: UIDevice.current.modelName,
            osVersion: UIDevice.current.systemVersion,
            appVersion: Bundle.main.appVersion,
            availableMemoryMB: ProcessInfo.processInfo.availableMemoryMB
        )
        
        let payload = FeedbackPayload(description: description, context: context, attachments: attachments)
        try await FeedbackAPIClient.shared.submit(payload)
        
        ToastManager.shared.show("反馈已提交，感谢您的帮助！", type: .success)
    }
}

// RemoteConfig.swift - 热修复配置
@Observable
final class RemoteConfig {
    static let shared = RemoteConfig()
    
    private(set) var aiPromptVersion: String = "v1.0"
    private(set) var proactiveTriggersEnabled: Bool = true
    private(set) var kanbanViewDisabled: Bool = false
    
    func refresh() async {
        guard let config = try? await ConfigAPIClient.fetch() else { return }
        self.aiPromptVersion = config.aiPromptVersion
        self.proactiveTriggersEnabled = config.proactiveTriggersEnabled
        self.kanbanViewDisabled = config.kanbanViewDisabled
    }
}

💡 终极交付哲学

“乘风计划”的RC阶段，本质上是在践行一种 “敬畏用户” 的工程伦理：
测试不是找Bug，而是定义可接受的行为边界——每一条测试用例都是对用户承诺的编码化表达；
性能不是数字游戏，而是对用户时间的尊重——每一毫秒的优化都在减少认知摩擦；
隐私不是合规成本，而是信任资产的积累——每一次加密、每一次权限克制都在构筑长期护城河；
发布不是终点，而是与用户共同进化的起点——灰度、反馈、热修复构成了持续学习的神经回路。

当这些工程实践内化为团队肌肉记忆，“乘风计划”便不再仅仅是一个效能工具，而成为一种可靠、透明、以人为本的数字生活方式载体。愿这份RC指南助您平稳抵达发布彼岸，让每一位用户都能在风中安心前行。
